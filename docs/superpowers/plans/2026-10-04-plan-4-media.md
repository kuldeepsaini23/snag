# Plan 4 — Video & audio downloads via yt-dlp (`rdm-media`)

> Compact format (interfaces + tests), executed inline. **Spec:** §2.2, §4. **Branch:** `feat/media` (from `feat/basic-ui`).

## `rdm-media` (does not depend on the engine)
```rust
pub enum MediaFormat { Video { max_height: u32 }, AudioMp3 }              // serde
pub struct QualityOption { label: String, format: MediaFormat, approx_size: Option<u64> }
pub struct Entry { url: String, title: String }
pub struct MediaInfo { title: String, duration: Option<f64>, options: Vec<QualityOption>, entries: Vec<Entry> }
pub fn is_media_url(url: &str) -> bool;                                   // youtube, vimeo, x, instagram, tiktok, …
pub fn parse_probe(json: &str) -> Result<MediaInfo, String>;              // `yt-dlp -J --flat-playlist`
pub fn build_args(format: &MediaFormat, out_dir: &Path, url: &str) -> Vec<String>;
pub struct MediaProgress { downloaded: u64, total: Option<u64>, speed_bps: u64 }
pub fn parse_progress_line(line: &str) -> Option<MediaProgress>;          // "RDMP <done> <total> <estimate> <speed>"
pub async fn probe(ytdlp: &Path, url: &str) -> Result<MediaInfo, String>;
pub async fn download(ytdlp, url, &MediaFormat, out_dir, CancellationToken, &watch::Sender<MediaProgress>)
    -> Result<MediaOutcome, String>;                                      // Completed(PathBuf) | Paused (process killed)
pub const YTDLP_URL: &str;                                                // GitHub latest yt-dlp.exe
```
- Video selector: `bv*[height<=H]+ba/b[height<=H]` + `--merge-output-format mp4`. Audio: `-x --audio-format mp3 --audio-quality 0`.
- The final path comes from `--print after_move:RDMF %(filepath)s`. Progress uses `--progress --progress-template`.
- Pause kills the process. On resume, yt-dlp continues its own `.part` files (same output template).

## `rdm-core` additions
- `Item.kind: Kind { Http (default), Media(MediaFormat) }` (old `state.json` files still load).
- `Manager::probe_media(url)`: downloads yt-dlp to `<state dir>/bin/yt-dlp.exe` through the engine if it's missing (one download at a time), then probes the link.
- `Manager::add_media(url, title, format)` creates a `Media` item, so the category is Video or Music.
- A media item runs `rdm_media::download` instead of the engine, and its progress maps onto the same `Progress`.

## Basic UI additions
- A media link (`is_media_url`) is probed first. A **picker** screen then lists the quality options with sizes (for a playlist, "N videos"), with Download and Cancel.
- `Picker::requests()` → one `(url, title, format)` per video. This is pure and tested.
