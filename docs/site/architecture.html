Architecture

How Snag is built

A Windows download manager in Rust, plus a browser extension. This page explains the pieces, how they talk to each other, and where your files and settings live.

Overview

Three places, one job

BROWSER

The extension

Spots videos and files in your tabs, shows the Download button and menu, and hands links to the app.

YOUR PC

The Snag app

One program (snag.exe) with the window, the tray icon and a small private server only your PC can reach.

THE INTERNET

The websites

Snag downloads straight from them over its own connections, with your cookies so they treat it like your browser.

System map

Everything on one board

Arrows show who asks whom. Purple lives in the browser, orange is the app's brain and window, blue does the downloading, green is what ends up on disk.

The extension never downloads anything itself. It only passes links to the app on 127.0.0.1.

A download, start to end

Clicking a NOW row

The same path every download from the browser takes. Numbers follow the order things happen.

Steps 1–3 happen while you watch. Steps 4–8 happen after one click.
Fast file downloads

Eight parts at once

For a normal file (a ZIP, an installer, a direct MP4), the engine asks the server for the size, splits the file into up to 8 parts and downloads them side by side with Range requests. Progress is written next to the file in a small .rdmstate note, so a pause, a crash or a restart continues where it stopped.

Streams & repair

Playlists of clips

Streaming sites send a playlist (.m3u8) listing hundreds of short clips. yt-dlp fetches them in order and joins them. If a site wrapped each clip in a fake picture to fool downloaders, Snag strips the wrapping afterwards so the file plays.

Extension ↔ app API

What the extension can ask

Every request except /ping and /pair must carry the pairing token. The server only listens on 127.0.0.1, so other computers can't reach it, and websites can't read its answers.

RouteWhat it does
GET /ping“Are you there?” Answers with whether the extension is paired and the accent colour.
POST /pairOne-click connect: Snag asks you “Allow?”, then hands over the token. Only browser extensions may ask.
POST /addAdd a link. Snag decides: file, video page, image gallery or torrent.
POST /probeRead a video page with yt-dlp and return its qualities (used by the menu and the prefetch).
POST /add-mediaAdd a video in the chosen quality, with cookies and Referer. Used by NOW rows and quality rows.
POST /add-batchAdd many links at once (“Grab all from this page”).
POST /focus, /quitBring the window forward; close Snag cleanly.
Where things are saved

Your disk

state.json
The download list, queues and settings. Written safely (temp file, then swap).
snag.log
Errors and notices, kept under 1 MB. Handy for bug reports.
bin\
yt-dlp and gallery-dl, fetched on first use. yt-dlp updates itself weekly.
cookies\
Short-lived cookie files for yt-dlp, deleted as soon as a download ends and wiped at start.
*.rdmpart / *.rdmstate
An unfinished file and its progress note. Both disappear when the file is complete.
Glossary

Words on this page

Sniffer
The part of the extension that looks at the addresses tabs load and keeps the ones that are media.
Referer
“I came from this page.” Many video servers only answer requests that say they come from their own player.
Cookies
Small notes your browser keeps for each site, like “logged in as you”. Snag borrows them so private or age-restricted videos work.
HLS / .m3u8
A streaming format: a playlist plus many short clips.
Range request
Asking a server for only part of a file (“bytes 15,000,000 to 29,999,999”). This is what makes parallel parts possible.
Pairing token
A secret shared once between the extension and the app, so only your extension can add downloads.
yt-dlp
An open-source tool that knows how to read 1,800+ video sites.
Prefetch
Reading a video page in the background as soon as it opens, so the quality list is ready when you click.
